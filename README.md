# asis-flow-skill

業務マニュアル・手順書（PowerPoint・PDF・Excel・マクロ付き Excel・Word・画像）から、as-is の業務フローを所定の draw.io テンプレートで作る Claude Code スキル。EUC・プログラムのソース（Excel マクロ・Access の書き出し・スクリプト・SQL など）も入力にでき、業務フローのどこでそのシステムが使われるかを明記し、プログラムのアクティビティ図を、業務フローと紐付けて別に出す。

進め方は、棚卸し → ページ画像化 → 階層の事前チェック → LLM がページ画像を見て読取 → 用語・資料の紐付け・業務分類の確定 → フロー化 → draw.io 書き出し → 機械チェック → 画像で目視 → 原典照合レビュー → 報告書 → 納品の門、の順。手順は [SKILL.md](SKILL.md)、決まりは [references/flow-rules.md](references/flow-rules.md) にある。

拠点ごと（海外拠点・支店）のマニュアルを比べて、拠点間の業務の差を出すときは、このスキルを拡張した [site-compare-skill/](site-compare-skill/README.md)（拠点間比較）を使う。拠点ごとの as-is はこのスキルで作り、比較の側で、用語・業務種別・タスクを突き合わせ、拠点タスク一覧・拠点のタスク別業務フロー・複雑性ヒートマップを出す。

## 考え方

- **原典に書いてあることだけを図にする。** 書いていないことは補わず、推定として印を付けて確認事項に出す。
- **全ノードに出典（資料・ページ・原文の引用）を付ける。** ノード → ページ、ページ → ノードの両方向を機械で確かめる。
- **LLM は XML を書かない。** LLM が書くのは JSON（ページカード・階層・用語・業務分類・フロー）。図は `build_drawio.py` がテンプレートのスタイルで組む。構文の破綻とスタイルの逸脱が起きず、機械チェックが効く。
- **形と数は機械が決める。** JSON の形はスキーマ（`assets/schemas/`）で確かめ、余分な項目・型違いは FAIL。ノードの番号・ページ番号の引き当て・材料の大きさは、スクリプトが数える。決まりで決まる所（確認事項の重要度・終了条件・書かれていない側の分岐のラベル・紐付けの根拠の写し・用語の対応の根拠）も機械が当て、LLM は名付けと判断だけをする。
- **点検は3段と、納品の門。** 機械チェック FAIL 0 → PNG と照合シートの目視 → 作り方を知らない別エージェントによる原典照合レビュー（採否表。支持率 95% 未満は FAIL。照合のあとに図を直したら、変わった箱だけを照合し直す）。最後に `deliver.py` が、書き出しと点検を決まった順に回し直し、全部通ったものだけを出力先に写す。[consulting-pptx-skill](https://github.com/carnot-tech/consulting-pptx-skill) の方式（正典・機械チェック・比較しての目視・フレッシュアイ・レビュー）にならっている。

## 精度と規模のための仕組み

| ねらい | 仕組み |
| --- | --- |
| 出力が毎回ぶれない | 全工程の出力にスキーマ（`validate.py`）。迷いやすい判断の決め方を正典に明記（種別の決定表・補足の置き場など）。カードの手順に id を振り、フローの出典が id で引く。用語の正本（`glossary.json`）。2回の結果の一致率を測る `diff_runs.py` |
| 補足の中の作業を落とさない | 注記・ただし書き・囲みの中の「〜する」を機械が候補に挙げ、手順にも「作業でない」の記録にも無ければ FAIL。カードの手順・分岐は、フローに入れるか対象外の理由を書く（どちらでもなければ FAIL） |
| ページがずれない | 出典は資料に刷られたページ番号で出す（Excel はシート名とセル）。データの鍵（ファイルの番号）と分ける。隣のページとの取り違え・系統的なずれ・目次が指すページ・ページ画像と機械抽出のずれを FAIL で名指しする |
| 複数の資料の親子構造 | 骨格は業務の木。資料の節を業務に結び付け（書いている／詳しくしている）、資料どうし・業務どうしの関係は決まった種類だけを根拠つきで持つ。上位フロー → 下位フローのリンクに落とす |
| プログラム（EUC・ソース）の中身も、根拠つきで | プログラムは実行せず、文字として読む（認証情報は機械が伏せる）。分岐・繰り返し・呼び出し・入出力・起動点は、機械がソースから取り出す。LLM は名付けとまとめだけ。実行文の行が、どれかの箱か「対象外」に1回だけ入ること（行の網羅）・分岐が、判断か理由つきの畳みのどちらかにあること（分岐の網羅）を機械が確かめる。業務フローとの紐付けの根拠は3種類だけ（名指し・入出力の一致・推定）で、文字が両側にあることを機械が確かめる |
| アクティビティ図を、業務部門の担当が読める | 箱・判断・図の名前には、業務の言葉だけを書く。画面・シート・ファイルに出てくる名前だけを、ソースの文字のまま「」で出す。プログラムの中の名前（変数・項目・手続き）を、どの言葉で書いたかは「プログラムの用語対応」（根拠: コメント／定義／つづりからの推定／不明）に残り、一覧のシートから引ける。箱にそのままの名前が出ていれば、機械が FAIL にする。分かれた道は横に並べ、途中で終わる所は、その場に終了の丸を置く（線・箱が重なるページは、機械が列を減らして描き直す）。名前の無い箱が残る図は【下書き】と出る |
| 図が読みやすく、確認事項が絞られている | 箱の名前は動詞で終え（機械が点検）、補足はかっこ書き。出典は、枠の外（箱・ひし形の右下）に、切らずに出す（ひし形が縦に伸びない。列は、出典が収まる幅に広げる）。レーンは、機械が、線がまたぐレーンの数が少なくなる順に並べる（開始の担当が左端・システムが右端。直しの一覧で指定もできる）。確認事項は、答えで図が変わる問いだけ（箱／順序／分岐／担当／システム・帳票／フローの範囲 のどれが変わるかを、必ず書く。値だけ・いまも同じか・名前だけの問いは、出さない） |
| 納品物の様式が、毎回同じ | 欄と見た目は、テンプレートが決める（業務フロー・アクティビティ図の `.drawio`、業務マトリクス一覧・確認事項一覧の `.xlsx`）。中身は、機械が同じデータから流し込み、LLM は書かない。お客様の様式には、テンプレートを差し替えて合わせる（列の順・見出し・人が埋める列・色・凡例の文）。決まりを外れたテンプレートは、機械が FAIL にする |
| 照合した中身と、納品する中身が同じ | 照合シートを作るたびに、照合に出した版（箱ごとの名前・レーン・補足・使うシステム・出典のページと行・前後の線と、図の印）を、シートの番号［S-<n>］で記録に残し、報告にその番号を書かせる（採否表を消しても、報告を書き直しても、照合した版は変わらない）。照合のあとに直した箱（採用した指摘の反映も）は、点検が「照合したあとに変わった・足した箱」として止め、その箱の出典ページだけの照合シートで照合し直させる（差分照合）。採用した指摘を図に反映していなければ、止める |
| 処理時間を、見直しの前と後で同じ物差しで比べる | 基準の表の版（表の値から作る印）を、ブックと納品の数に出し、表を直すと知らせる。納品の門が、現状の処理時間の写し（作業ごとの時間・人の値か仮の値か・合計）を残す。比べるのは、同じ版の表で出した時間どうし |
| 人が入れた値が消えない | 確認事項一覧の回答・回答者・回答日、様式で足した列、業務マトリクス一覧の処理時間・件数は、書き出し直すときに、いまあるブックから `answers.json`・`times.json` に取り込んで戻す。開いたままのブック・列を動かしたブックは、上書きせずに止まる |
| 点検が壊れても気づける | LLM・人が書くファイル（カード・業務分類・フロー・台帳・直しの一覧・木・採否表など）を見る点検は、どれも、誤りを 1 つ仕込んだ写しで FAIL が出ることを、自己点検で確かめる（点検が中継する、直しの一覧・台帳・ブロックの木・用語の対応・照合の報告・一覧の読み戻し・人の値の控えの誤りの文も、文ごとに）。確かめていない点検（機械が書くものの細部・守り）は、理由つきで `evals/untested_checks.md` に並べ、`evals/coverage.py` が、一覧の外に発火しない点検が無いかを数える |
| 大量の入力 | 読取の束を見込みトークンで切る（1つのエージェントの文脈の半分）。フロー化の材料に上限。点検の出力は畳む。状態は作業フォルダにあり、`status.py` で途中から続ける |

## セットアップ

```bash
pip3 install pymupdf python-pptx openpyxl pillow oletools
```

- Office 文書（pptx・xlsx・docx）をページ画像にするのに、次のどちらかが要る。`python3 scripts/office_to_pdf.py --probe` で使える方法が出る。
  - **LibreOffice**（`brew install --cask libreoffice`）: 画面を出さずに動くので確認ダイアログで止まらない。大量の入力・無人で回すときはこちら。Excel は1シート＝1ページで出る。あれば自動でこちらを使う。
  - **Microsoft Office（macOS）**: AppleScript で動かす。見た目は最も原本に近い。初回に macOS が「制御を許可するか」を尋ねる。Office が確認ダイアログ（アクセスの許可・起動時の案内・回復したファイルなど）を出すと止まるので、人が画面を見ていられるときに使う。止まったときは、その資料に理由を残して先へ進む。
- 図の PNG 書き出しに draw.io デスクトップ（`brew install --cask drawio`）。
- PDF・画像だけの入力なら、Office も LibreOffice も要らない。
- Python 3.9 以上。

**プログラムの取り込みで、実物で確かめたこと**（2026-10-13。名の通った公開プロジェクトのテスト用データ）:

- マクロ付きの Excel 22 ファイル（`.xlsm`・`.xlsb`・`.xls`・アドイン・暗号化つき）: モジュールと手続き、ボタン・図形とマクロの対応、シートのコード名、ショートカット、閲覧のロック、開けないファイルの扱い。
- Access の版管理アドインが書き出したフォルダ 2 つ（手続き 48・2,477）: 全手続きに構造ができ、行の網羅が 100%。マクロは、中の XML の定義から読む。
- Access のファイルの直接読み（`scripts/access_direct.py`。書き出しが入力に無いときに、棚卸しが自動で行う）: 同じ版の書き出しと突き合わせて、オブジェクトの一覧・クエリ・VBA のソース・フォームのコントロールとイベントの割り当て・マクロが一致（テーブルの項目は 31 のうち 30。添付ファイル型の呼び方だけが違う）。暗号化つき・97 以前の形式は読まず、その旨を確認事項にする。
- 構造を LLM が読む言語（実物の COBOL 2 本・Java 3 本）と、アクティビティ図 12 枚を、サブエージェント 4 体で測った。同じ下書きを2人が直した図の、箱の対応は 97%（242/250）、行と分岐の網羅は 100%。**原典との照合の支持率は 94.3%（115/122）で、目安の 95% に届かなかった。** 支持されなかった 7 箱のうち 6 箱は、線が重なって別の箱につながって見える図（中身と行き先は合っている）、1 箱は条件の無い繰り返しの描き方で、どちらも機械を直した（`references/flow-rules.md` 7 章の 2026-10-13 の記録）。
- アクティビティ図を、業務部門の担当に向けて作り直し（箱の名前を業務の言葉に・分かれた道を横に）、同じ 12 枚を照合 2 体で測り直した。**原典との照合の支持率は 95.3%（122/128）で、目安の 95% を満たした。** 支持されなかった 6 箱は、名前の言い換えの誤り 4 と、機械が読む先を落とした 2。支持率と別に数えた「担当に通じにくい言葉」は 38 件（技術の用語が大半）。どちらも直し、決まりを足した。前からあった 21 枚で、線どうしの交わりは 111 → 6、高さの合計は 4 分の 3（`references/flow-rules.md` 7 章の 2026-10-13 の記録）。
- 補助の手続きを図にしない決まり（共通の処理 18 のうち 11 を、理由つきで図から外した。図にする単位 37 → 26）と、納品物のテンプレート（表 2 つ・アクティビティ図）を入れ、12 枚（前回の 11 枚と、箱が変わった呼ぶ側の図 1 枚）を照合 2 体で測り直した。**原典との照合の支持率は 97.1%（135/139）。** 図にしない手続き 11 個の理由は、どれも中身と合った。支持されなかった 4 箱は、機械が読む先を取り違えた 2 と、呼び出しの箱の名前 2（どちらも、そのあとで直した）。既定のテンプレートで書き出した図と表は、テンプレートを入れる前と同じ（図は 1 文字も変わらない。表の違いは、足したシート「図にしない手続き」と、空の回答欄の持ち方だけ）。

**まだ確かめられていないこと**:

- 点検の場所 494（FAIL 301・門で FAIL に上げる WARN 10・共通の部品を呼ぶ所 32・点検が中継する、直しの一覧・アクティビティ図の直しの一覧・台帳・ブロックの木・取り出した構造・用語の対応・照合の報告・一覧の読み戻し・処理時間の基準の表・人の値の控えの誤りの文 151）のうち、誤りを仕込んで発火を確かめていないのは 20（2026-10-17。`check_flow.py`・`check_layout.py`・`apply_edits.py`）。どれも、機械が書く図・業務マトリクス一覧の細部（作り直しとの一致の点検が先に止める）か、試験の環境では作れない守りで、理由は `evals/untested_checks.md`。LLM・人が書くファイルを見る点検は、全部確かめている（点検が中継する誤りの文も、文ごとに。機械の取り出しの守り（取り出した構造の誤り）は、構造を直に作って確かめる）。正しいデータで FAIL が出ないことも、全部で確かめている
- 決め方を足したあとの木の一致（2人が読んだ COBOL の木は、足す前で 155/218）。測り直していない。
- 3 回目の照合のあとに直した所（接続の文字・クエリを相手にした集計の関数の読み方、番号が渡らないときは読まない手続きを呼ぶ箱の名前）を入れた図は、測り直していない。レーンの名前が、ファイルの名前から付くこと。
- 表のテンプレートに置いた図形（オートシェイプ）・グラフ・条件付き書式が、書き出した本に残るか（ロゴの画像・結合したセル・ヘッダーとフッターは、残る）。
- アクティビティ図の配置のうち、入れ子の分岐で、外側の道をさらに右へ逃がすこと（交わりが残る図がある）。用語の対応の言葉は、ソースから読んだもの（業務での呼び方は、一覧の「プログラムの用語対応」を担当に見てもらう前提。確認事項にはしない）。
- Access の書き出しの道具（`assets/access_export/`）を、Access の実物で動かすこと（読み比べての見直しまで）。道具が出す「生の」書き出しと、アドインの書き出しとの差。
- 直接読みのうち、レポート・古い形式のフォーム・フォームに埋め込んだマクロ・テーブルの関係・起動時のフォーム。フォームのイベントの番号は、1 組のファイルから求めたもの。
- `.xls`（古い形式）のボタンとマクロの対応、リボンの定義・閲覧のロックつきの実物。
- 日本語の業務で実際に使われている EUC（サンプルは、英語圏のテスト用で小さい物が多い）。
- 25 箱を超える図の自動の分割（いまは WARN を出すだけ。まとめる・畳むは、直しの一覧でする。同じ共通の処理を続けて呼ぶ並びは、下書きのままで 25 箱を超える図に、まとめの案が出る — 架空のソースの試験だけで、実物の 25 箱を超える図では使っていない）。出どころも行き先も違う線どうしが同じ所を重なって走る図は、配置の点検が FAIL にする（決まり 4.10）。セルの番地を見出しの名前に引き当てること。

## カスタマイズ

- いちばん効くのは `references/flow-rules.md` への追記。レビューで受けた指摘を1行ずつ足す。
- 納品物の様式は、`assets/` のテンプレート 4 つで決まる（守る形と差し替え方は `references/template-spec.md`）。図（`業務フロー図_テンプレート.drawio`・`アクティビティ図_テンプレート.drawio`）は、差し替えて `python3 scripts/harvest_template.py`。表（`業務マトリクス一覧_テンプレート.xlsx`・`確認事項一覧_テンプレート.xlsx`）は、写して Excel で直し、`python3 scripts/table_template.py check <様式.xlsx> --book matrix`（確認事項一覧は `questions`）で確かめてから、`assets/` に置くか、`build_matrix.py`・`build_reports.py` の `--template` で指す。
- チェックを足すときは `check_flow.py` に FAIL / WARN を足し、`evals/selftest.py` にその誤りを仕込んだケースを足す。`python3 evals/coverage.py -w <作業フォルダ>` で、発火を確かめていない点検が無いかを見る（試験しない点検は、理由を `evals/untested_checks.md` に書く）。
- JSON の項目を足すときは、`assets/schemas/*.schema.json` に説明つきで足し、`python3 scripts/validate.py --doc` で `schemas.md` を作り直す。
- 補足の中の作業の拾い方（目印・動作の言い回し）は `assets/action_markers.txt` を、資料の書きぶりに合わせて足し引きする。
- 束の予算（`pages.py batches --budget`）・材料の上限（`check_flow.py`・`pages.py plan-flows` の `--max-material`）は、使うモデルの文脈の大きさに合わせて変える。
