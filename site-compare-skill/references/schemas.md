# 比較のデータの形

**人・LLM・サブエージェントが書くもの**: 拠点の一覧（`sites.json`）・書き分け（`applies.json`）・用語の対応（`terms.json`）・比べる行（`axis.json`）・タスクの対応（`rows/<行>.match.json`）・報告（`reports/`）・採否表（`review/<行>.review.json` の採否と対応）。
**機械だけが書くもの**: 拠点の写し（`snap/<拠点>.json`）・計算の結果（`rows/<行>.result.json`）・通し番号（`numbers.json`）・照合に出した版の記録（`review/versions.json`）。手で直さない（点検が、作り直したものと比べる）。
人が値を入れて返すブック（`拠点比較.xlsx` の確認事項一覧）は、書き出し直すと回答を読み戻して残す（`answers.json` は asis と同じ形）。

**形はスキーマ（`assets/schemas/sc_*.schema.json`）が正。** この文書の項目表は、スキーマから `python3 scripts/sc_validate.py --doc` で作っている（手で直さない）。
スキーマに無い項目を足すと FAIL になる。書きたいことがどの項目にも当てはまらないときは、項目を作らずに親へ報告する（報告の `for_parent`）。
拠点 ID（`TK`）・行の ID（`B03`・`B03-1`）・業務分類の ID（`G01`）・タスクの ID（`t3`）・用語の組の ID（`R01`・`Y01`・`D01`）・箱の鍵（`F03-1:P-002`）の書式は、共通の定義（`sc_common.schema.json`）から引く。確認事項の形・フロー ID は asis の共通の定義（`common.schema.json`）から引く。

書いたら自分で確かめる: `python3 scripts/sc_validate.py -w <CMP> --kind match`（1 つのファイルなら `--file match <ファイル>`）。
実例は `evals/fixture_expected/`（架空の 3 拠点: 東京支店・大阪支店・シンガポール拠点の経費精算）。迷ったらそれを見る。

## 番号と鍵（ここを取り違えない）

| 番号 | 例 | どこで決まるか | 納品物に出るか |
| --- | --- | --- | --- |
| 拠点 ID | `TK` | `sites.json`（英大文字 2〜6 字。決めたあとは変えない） | 出ない（拠点の名前が出る） |
| 箱の鍵 | `F03-1:P-002` | 拠点の asis のフロー ID とノード番号。開いた下位フローの箱は、その子のフロー ID | 出ない |
| 項目の鍵 | `M01.2.s3` | 拠点の asis のカード（資料 ID・ページ・項目 ID）。外した手順・書き分けを指す | 出ない |
| 行の ID | `B03`・`B03-1` | `axis.json`（子の行は親の ID に `-<n>`） | 出ない（業務種別の名前が出る） |
| タスクの ID | `t3` | `rows/<行>.match.json`（行の中の番号。振り直さない・使い回さない） | 出ない |
| タスクの番号 | `T-005` | 機械（`numbers.json`。行とタスクの ID で引き継ぐ） | 出る |
| 確認事項の番号 | `Q-003` | 機械（`numbers.json`） | 出る |

箱の鍵は拠点ごと（`TK` の `F03:P-002` と `OS` の `F03:P-002` は別の箱）。どの拠点の箱かは、書く場所（`members.TK`）で決まる。
拠点のフローを直して番号が振り直されると、`sc_collect.py` が出典の指紋で鍵を付け直す（付け直せない箱は、点検が挙げる）。

## 拠点の一覧 `sites.json`

`sc_init.py` が入力のフォルダの形（`<入力>/<拠点>/`・`<入力>/共通/`）から下書きを書く。利用者と決めるもの: 基準の拠点・拠点の名前と別名・資料の言葉・共通の資料を使うか。

```json
{"baseline": "TK", "shared": {"inputs": ["/data/in/共通"]},
 "sites": [{"id": "TK", "name": "東京支店", "aliases": ["東京"], "language": "ja", "inputs": ["/data/in/東京支店"]},
           {"id": "OS", "name": "大阪支店", "aliases": ["大阪", "Osaka"], "language": "ja", "inputs": ["/data/in/大阪支店"]},
           {"id": "SG", "name": "シンガポール拠点", "aliases": ["シンガポール", "Singapore"], "language": "en",
            "inputs": ["/data/in/シンガポール拠点"], "uses_shared": false}]}
```

## 書き分け `applies.json`

`sc_applies.py draft` が候補（拠点の名前・別名・「拠点ごと」「支店によって」の出る項目と、同じページ・同じ小見出しの項目）を、scope「未定」で書く。LLM が項目ごとに scope と sites と evidence を決める。

```json
{"items": [
  {"key": "M01.2.s3", "doc": "bf992f…", "text": "申請を承認する", "mentions": [], "scope": "except", "sites": ["OS"],
   "evidence": "「大阪支店では、課長に代えて支店長が申請を承認する」とある（大阪支店では、課長は承認しない）"},
  {"key": "M01.2.s4", "doc": "bf992f…", "text": "申請を承認する", "mentions": ["OS"], "scope": "only", "sites": ["OS"], "evidence": "「大阪支店では」とある"},
  {"key": "M01.2.s1", "doc": "bf992f…", "text": "申請の内容と領収書を照合する", "mentions": [], "scope": "all", "sites": [],
   "evidence": "拠点の書き分けの無い手順（同じ節にあるので拾った）"}],
 "questions": []}
```

## 用語の対応 `terms.json`

`sc_terms.py draft` が、名前が同じ用語だけを 1 つの組にした下書きを書く。LLM は、訳・言い換えで同じものを、理由つきでまとめる（`references/terms-guide.md`）。

```json
{"groups": [
  {"id": "R03", "kind": "actor", "name": "経理", "members": [{"site": "TK", "term": "経理部"}, {"site": "OS", "term": "経理担当"}, {"site": "SG", "term": "Finance"}],
   "basis": "equivalent", "reason": "どの拠点も、承認済みの申請の支払データを作り、振込（銀行振込）で支払う担当"},
  {"id": "Y02", "kind": "system", "name": "会計システム", "members": [{"site": "TK", "term": "会計システム"}], "basis": "same_name", "reason": ""}],
 "questions": []}
```

## 比べる行 `axis.json`

`sc_axis.py draft` が、基準の拠点（無ければ 1 つ目の拠点）の業務分類から行を作る。LLM は、ほかの拠点のフローを行に当て、どれにも当たらない業務は行を足す（`references/axis-guide.md`）。
`rows` の並びが、表と図の並び。`parts[].nodes` は、1 本のフローの一部だけをこの行に入れるとき（`split`）だけ書く（null は全部）。

```json
{"mode": "baseline",
 "groups": [{"id": "G01", "name": "経費精算", "name_from": null}],
 "rows": [
  {"id": "B02", "group": "G01", "parent": null, "name": "承認", "name_from": {"site": "TK", "flow": "F02"}, "origin": "baseline",
   "sites": [{"site": "TK", "relation": "same", "parts": [{"flow": "F02", "expand": true, "nodes": null}], "reason": ""},
             {"site": "OS", "relation": "same", "parts": [{"flow": "F02", "expand": true, "nodes": null}], "reason": ""},
             {"site": "SG", "relation": "split", "parts": [{"flow": "F01", "expand": true, "nodes": ["F01:P-002", "F01:SUB-001"], "title": "申請と承認（承認の箱）"}],
              "reason": "申請と承認を 1 本（Claim and approval）に書いている。承認の箱をこの行に"}]}],
 "not_compared": [], "questions": []}
```

## タスクの対応 `rows/<行>.match.json`

`sc_match.py draft` が、基準の拠点の作業の箱 1 つ＝1 タスクの下書きを書く。行ごとに 1 体のサブエージェントが、ほかの拠点の箱を入れ、粗い方に合わせてまとめ、記載なし・内容の差を書く（`references/match-guide.md`）。
並び・区分・記号・差の種類・粒度・複雑性・番号は、機械が決める（ここに書かない）。

