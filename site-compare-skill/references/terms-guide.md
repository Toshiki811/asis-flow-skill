# 用語の対応の進め方（工程 3）

拠点ごとに、担当・システム・帳票の呼び方は違う（言葉も違う）。用語の対応（`terms.json`）が無いと、担当の差・システムの差・受け渡しの数を、拠点をまたいで比べられない。
用語は少ない（拠点あたり十数〜数十）ので、親（進行役）が書いてよい。多ければ、種類（担当・システム・帳票）ごとにサブエージェントに分ける。

## 進め方

1. `python3 scripts/sc_terms.py draft -w <CMP>` — 拠点の写しに出る用語を拾い、名前が同じものだけを 1 つの組にした下書きを書く（すでにある組には触らない）。
2. `python3 scripts/sc_terms.py list -w <CMP>` — 用語ごとに、拠点・使われている箱の数・いまの組。
3. 訳・言い換えで同じものを、1 つの組にまとめる（`references/compare-rules.md` 2 章）:
   - 組の `members` を 1 つにまとめ、`basis` を `translation`（訳が同じ）か `equivalent`（呼び方は違うが、役割・担う作業が同じ）にし、`reason` に原典の根拠（役割の説明・担う作業）を書く。`reason` は日本語で書く（納品物の「拠点間の用語対応」に出る。原文の引用は書かない。英字のままでよいのは、用語と資料の名前だけ）。
   - どの作業を担っているかは、`python3 scripts/sc_axis.py material -w <CMP>`（拠点ごとのフローの担当と作業）と、拠点の写し（`snap/<拠点>.json` の箱）で見る。
   - 同じ拠点の 2 つの用語を 1 つの組にしない。名前が似ているだけでまとめない。製品が違うシステムは別の組。
   - 担当・帳票の組の名前（`name`）は日本語にする（納品物のレーン・帳票の名前になる）。
   - 決められなければ別の組のままにし、`questions` に種別「用語」・`group` に組の ID・`effect`「差の種類」で書く。
4. 使われなくなった組は消す。組の ID は振り直さない（R01・Y01・D01 の番号は、足すときは次の番号）。
5. `python3 scripts/sc_check.py -w <CMP> --stage terms` を FAIL 0 に。

## 例

```json
{"id": "R03", "kind": "actor", "name": "経理", "members": [{"site": "TK", "term": "経理部"}, {"site": "OS", "term": "経理担当"}, {"site": "SG", "term": "Finance"}],
 "basis": "equivalent", "reason": "どの拠点も、承認済みの申請の支払データを作り、振込（銀行振込）で支払う担当"}
```
