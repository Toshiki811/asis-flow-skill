# Access のファイルの読み方（書き出し・直接読み）

入力に Access のファイル（`.accdb`・`.mdb`・`.accda`）があるときに使う。読み方は3つあり、上のものがあれば、それを使う。

| 読み方 | いつ | 読めるもの |
| --- | --- | --- |
| **書き出したテキスト**（この資料の道具 `assets/access_export/`） | Access のあるパソコンで、書き出してもらえるとき。**いちばん確か** | フォーム・レポート・マクロ・モジュール・クエリ・テーブル・リレーション・起動時に開くフォーム |
| **版管理アドインの書き出し**（msaccess-vcs-addin の `<ファイル名>.src/`） | 開発している人が、すでにそのフォルダを持っているとき | 同上（下の「ほかの道具で書き出したフォルダ」） |
| **直接読み**（`scripts/access_direct.py`。棚卸しが自動で行う） | 書き出したテキストが入力に無いとき。Access が手元に無くても読める | VBA・テーブル・クエリ・フォームの定義（2007 以降の形）・XML の定義のあるマクロ。**読めない部分がある**（下の「直接読み」） |

> **確かめられていないこと**: 書き出しの道具（`assets/access_export/`）そのものは、Access の実物で動かして確かめていない（作った環境に Windows と Access が無い）。使っている命令（`NewCurrentDatabase`・`DBEngine.OpenDatabase`・`TransferDatabase`・`SaveAsText`）のうち、`SaveAsText` と `NewCurrentDatabase` の引数と、出力の文字コードは、同じ命令を実地で使っている版管理アドインの実装と読み比べて確かめた。`TransferDatabase` での取り込みと、DAO の読み取り専用での読み方は、読み比べる相手が無い。はじめて使うときは、写しで試し、`access_export.txt` と、書き出されたファイルを利用者と一緒に見る。動かなければ、出たメッセージをもらって直す。
>
> 書き出したテキストの**読み取り**（このスキルの `extract_access.py`）は、実物の書き出し（版管理アドインの2つのデータベース。フォーム 21・レポート 3・マクロ 2・VBA 約 7.7 万行）で確かめた。記録は `evals/real_samples.json`。

## 利用者にお願いすること

Access の入っているパソコン（Windows）で、次のどちらかを行う。

**A. スクリプトで書き出す（ふつうは、こちら）**

1. Access のファイルの**写し**を作る（元のファイルは使わない）。
2. `assets/access_export/access_export.vbs` を、同じパソコンに置く。
3. 写しのファイルを、`access_export.vbs` の上にドラッグして落とす。
4. Access の画面が開いて、しばらく動く。触らずに待つ。終わると「Finished.」と出る。
5. 写しと同じ場所に、`<ファイル名>_export` というフォルダができる。**フォルダごと**渡してもらう。

**B. スクリプトが動かないパソコン（`.vbs` の実行を止めている会社）**

1. Access のファイルの写しを作る。
2. Access を起動し、**空の新しいデータベース**を作る（読みたいファイルは開かない）。
3. Alt+F11 で Visual Basic の画面を開き、［ファイル］→［ファイルのインポート］で `assets/access_export/access_export.bas` を選ぶ。
4. いちばん下の `AsisFlowAccessExport` の中にカーソルを置いて F5 を押す。写しのファイルの場所（フルパス）を入れる。
5. あとは A と同じ。

どちらも、中身は同じ（共通の部分は、同じ文字）。メッセージは英語で出る（どの文字コードの Windows でも動くように、ファイルを ASCII だけで書いてある）。

| 出るメッセージ | 意味 |
| --- | --- |
| `Finished.  Written: 12  Failed: 1` | 終わった。書き出せた数と、書き出せなかった数 |
| `File not found` | 指定したファイルが無い |
| `Microsoft Access was not found on this PC` | そのパソコンに Access が入っていない |
| `Could not open the file read-only. Files that need a password are not read` | 開くのにパスワードが要る・ほかの人が排他で開いている・古すぎる形式。パスワードが要るファイルは、保護を外した写しをもらう |
| `Could not make the temporary database` | 書き出し先のフォルダに書き込めない |

書き出しの途中で、パスワードを聞く画面が出たら、入れずにキャンセルしてもらう（VBA のプロジェクトにロックが掛かっている。読んでよいかは、別に利用者に確かめる）。

## 道具がすること・しないこと

- **元のファイルを、Access で開かない。** 空の新しいデータベースを作り、そこへフォーム・レポート・マクロ・モジュールを取り込んで、テキストに保存する。テーブルとクエリは、データベースの部品（DAO）で、読み取り専用で読む。元のファイルを「いま開いているデータベース」にしないので、起動時に開くフォーム・AutoExec マクロ・コードは動かない。
- **元のファイルに書き込まない。** 作るのは、書き出し先のフォルダと、その中の仮のデータベース（`_access_export_tmp.accdb`。終わると消す。残っていたら消してよい。入力にあっても、このスキルは読まない）。
- **テーブルの行の中身は書き出さない。** 項目の名前と型・主キー・件数・リンク先・リレーションだけ。
- **接続文字列のパスワードは、`***` に置き換えて書く**（`PWD=…`・`PASSWORD=…`）。ページ化のときにも、機械がもう一度伏せる。

## 書き出されるもの

| ファイル | 中身 | このスキルでの扱い |
| --- | --- | --- |
| `access_export.txt` | 元のファイルの名前・Access の版・書き出したものの一覧・書き出せなかったものと理由 | システムの名前（元のファイルの名前）。書き出せなかったものは、確認事項に自動で載る |
| `access_tables.txt` | テーブルの定義（項目・型・主キー・件数）、リンク テーブルの接続先、リレーション、起動時に開くフォーム | 定義として持つ（図にはしない） |
| `access_queries.sql` | 保存してあるクエリの名前・種類・SQL | クエリを動かす文の箱に、その SQL が読む・書くテーブルを付ける。出典に、SQL の行が入る |
| `F_<名前>.form.txt` | フォームの定義（コントロールと、イベントに割り当てたもの）と、コード | イベントに割り当ててあるコード・マクロ・関数の式・埋め込みマクロを起動点にする。ボタンの文字・項目のラベルを、起動点の名前に使う |
| `R_<名前>.report.txt` | レポートの定義と、コード | 同上 |
| `X_<名前>.macro.txt` | マクロ（アクションの並び） | アクションの並びを手続きとして読む（条件・`RunCode`・`RunMacro`・`OpenQuery` ほか） |
| `M_<名前>.bas` | 標準モジュール・クラス モジュール | VBA として読む |

1つの Access のファイルを書き出したフォルダは、全部で1つのプログラムのまとまりになる（フォームのボタン → マクロ → VBA の関数、のように、またいで呼び出しを追う）。

## 取り込み方

書き出したフォルダを、入力のフォルダに入れて、いつもどおりに進める（`code-guide.md`）。

```bash
python3 scripts/extract_access.py <書き出したフォルダ>     # 読めた中身を、まず目で見る（フォームのイベント・マクロ・クエリ・テーブル）
python3 scripts/inventory.py <入力> -w <WORK>
python3 scripts/render_pages.py -w <WORK>
python3 scripts/code_struct.py -w <WORK>
```

- Access のファイルそのもの（`.accdb`・`.mdb`）が入力に一緒にあってもよい。書き出したフォルダ（`access_export.txt` の `source` が、そのファイルの名前）があれば、ファイルのほうは開かずに、書き出しのほうを読む。書き出しが無ければ、棚卸しが直接読む（下の「直接読み」）。直接も読めないファイルは、「読めていない資料」として確認事項に載る。
- マニュアルが無く、Access の書き出しだけでもよい。その場合、業務フローは作らず、アクティビティ図と、システム・起動点の一覧を出す（`check_flow.py` と `status.py` は、マニュアルの工程を求めない）。
- ほかの道具で書き出したテキスト（`SaveAsText` の出力）も、先頭の形で見分けて読む（`Version =…` と `Begin Form`／`Begin Report`、マクロは `ColumnsShown =`）。名前は、ファイル名から取る。

## ほかの道具で書き出したフォルダ（版管理アドイン）

Access の版管理アドイン（msaccess-vcs-addin）で書き出したフォルダ（`<ファイル名>.src/`。中に `vcs-options.json`・`vbe-project.json` がある）は、そのまま入力にできる。フォルダ1つが、1つのプログラムのまとまりになる。

| 場所 | 読み方 |
| --- | --- |
| `forms/<名前>.form`・`reports/<名前>.report` | フォーム・レポートの定義。コードは、隣の `<名前>.cls`（定義のあとに続けて、1つのモジュールとして読む） |
| `macros/<名前>.macro` | マクロ。XML の定義（`_AXL:` の行）があれば、条件のブロックを、そのとおりに読む |
| `modules/**/*.bas`・`*.cls` | VBA |
| `queries/<名前>.sql` | クエリ（種類は、SQL の先頭の語から） |
| `tbldefs/<名前>.sql`・`<名前>.json` | テーブルの定義（`CREATE TABLE`）・リンク テーブル |
| `vbe-project.json`・`dbs-properties.json` | 元のファイルの名前・起動時に開くフォーム |
| 画像・テーマ・メニュー・`tables/`（行の中身）・設定の JSON・`AGENTS.md` ほか | **読まない**（資料に数えない。棚卸しが、件数を知らせる） |

このアドインの書き出しは、Access の出力を整えたもの（色やプリンタの設定の行を落とし、識別子の大小を揃える）。図に使う行（コントロールの名前・表示の文字・イベントの割り当て・コード）は、そのまま入っている。

## 直接読み（`scripts/access_direct.py`）

書き出したテキストが入力に無い Access のファイルは、**棚卸し（`inventory.py`）が、ファイルを直接読んで**、書き出しの道具と同じ形のテキストを `<WORK>/direct/<ファイル名>_direct/` に作る（`--no-direct` で止められる）。あとは、書き出しと同じ道具が読む。Access は使わない。ファイルのバイトを読むだけで、マクロも VBA も実行しない。元のファイルには書き込まない。入れる部品は無い（VBA の圧縮を戻すのに、マクロ付き Excel と同じ `oletools` を使う）。

```bash
python3 scripts/access_direct.py <ファイル>                  # 読めた中身を、まず目で見る
python3 scripts/access_direct.py <ファイル> --out <フォルダ>  # テキストを、手で作る（棚卸しがしているのと同じ）
```

Access のファイルの形式に、公式の説明は無い。ページとレコードの形は公開されている解析、VBA は公開の仕様（MS-OVBA）、フォームの定義とマクロの入れ物は、**実物（ファイルと、その書き出しが対で公開されているもの）と突き合わせて**読み方を決めた。使うのは、答え合わせで合った部分だけ。

| 読むもの | 実物での答え合わせ | 扱い |
| --- | --- | --- |
| オブジェクトの一覧（名前） | フォーム 17・マクロ 1・モジュール 140・クエリ 5・テーブル 6 が、書き出しと全部一致 | 使う |
| VBA のソース | 157 モジュール・約 7.7 万行が、行ごとに一致（Attribute の見出しの行と、識別子の英字の大小 32 行を除く） | 使う。構造の段は、書き出しと同じ「機械（構文から）」 |
| テーブルの定義（項目・型・主キー・件数） | 31 項目のうち 30 が一致。残る 1 は添付ファイル型で、書き出しの側が別の型に書いている | 使う。行の中身は読まない |
| クエリ | 公開のテスト（Jackcess）の期待値 36 件と一致（うち 4 件は、結合の条件を AND で並べる順だけが違う）。書き出しの 5 件とも一致 | 使う。**SQL の文は、ファイルに入っていない**ので、部品から組み立てる。Access が表示する文と、書き方（かっこ・角かっこ・条件の順）が違うことがある |
| フォームの定義（コントロールの名前・種類・表示の文字・イベントの割り当て） | 17 フォーム・567 個のオブジェクトの入れ子が全部一致。コントロール 407／407、イベントの割り当て 70／70 | 使う（Access 2007 以降の形で保存されたフォームだけ）。下の注意 |
| マクロ | XML の定義（1 件）が、書き出しと一致 | XML の定義があるものだけ使う |
| 通しでの構造 | 直接読みから作った構造が、書き出しから作った構造と同じ（手続き 2,477・起動点 73 とその名前・図にする単位 386） | ― |

**読まないもの・読めないもの**（どれも、黙って落とさない。確認事項に、自動で載る）:

- **暗号化・パスワードつきのファイル、Access 97 以前の形式**は、読まない。書き出しの手順を案内する。
- **レポートの定義**は、答え合わせのできる実物が無いので、使わない。**前の形で保存されたフォームの定義**（Access 2003 までに作って、そのあと保存し直していないもの）は、形が違って読めない。どちらも、コードはあるので、手続きの名前（`コントロール名_イベント`）から**起動点の候補**を出し、名前に「（割り当ては未確認）」と付ける。イベントに割り当ててあるかは、書き出しで確かめる。
- **フォームのイベントの種類**は、番号で入っている。名前の分かっている番号は 10 種類（Open・Close・Load・Unload・Resize・Timer・Click・DblClick・BeforeUpdate・AfterUpdate。実物から割り出した）。**ほかの番号**に `[Event Procedure]` が入っていれば、そのコントロールの手続きの名前から種類を決め、根拠に「イベントの種類は、手続きの名前から」と書く。数が合わないときは、確認事項に載せる。
- **XML の定義が無いマクロ**（Access 2007 より前の形のまま）と、**フォームに埋め込んだマクロ**は、読めない。
- **マクロのうち、ファイルやシートを読み書きするアクション**（`ImportExportSpreadsheet`・`ExportWithFormatting` など）は、文として図に置くが、読み書きするものは取らない（引数の並びを、XML の名前から決められない）。呼び出し・クエリ・フォームを開く・メッセージは、書き出しと同じに読む。
- **リレーション**と、**起動時に開くフォーム**は、読んでいない。
- コンパイル済みのファイル（`.accde`・`.mde`）には、ソースが入っていない。

直接読んだまとまりには、確認事項「Access のファイルを直接読みました。次の点は、読めていないか、確かめられていません…」が1つ載る。図や台帳を確かなものにするには、Access のあるパソコンで書き出してもらい、そのフォルダを入力に足す（足せば、直接読みは使われなくなる）。

## 読めないもの・気をつけること（書き出し）

- **コンパイル済みのファイル（`.accde`・`.mde`）**には、コードが入っていない。フォーム・レポート・モジュールは書き出せない（`access_export.txt` に FAILED と出る）。元の `.accdb`・`.mdb` をもらう。
- **マクロ**は、アクションの行（`Action =`）に加えて、XML の定義（`_AXL:` で始まるコメントの行）が入っていることがある（Access 2010 以降の、If・Else のブロックのあるマクロ）。あれば、条件のブロックを XML のとおりに読む（構造の段は「機械（構文から）」）。アクションの行だけなら、条件の列から読む（「機械（行の形から）」）。XML とアクションの行の対応が取れないときは、行の形のまま読んで、確認事項に載せる。
- **フォームの定義で、イベントに割り当てていない手続き**（プロパティが空で、コードだけ残っている）は、起動点にしない。「どの起動点からも呼ばれていない手続き」として確認事項に載る。
- **リンク テーブル・パススルー クエリ**の先（ほかのデータベース・サーバー）の中身は、読めない。接続先の名前だけが分かる。
- **データ マクロ**（テーブルに付いたマクロ）・リボンの定義・ナビゲーション ウィンドウの並びは、読んでいない。
