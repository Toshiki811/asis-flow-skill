# ページ読取の進め方（工程4）

ページ画像を LLM が見て、1ページ1枚のページカードを書く工程。フローの正しさはここで決まる。あとの工程はカードしか見ないので、ここで落としたものは図に出ず、ここで作ったものは図に残る。

## 親（進行役）のやること

1. `python3 scripts/pages.py batches -w <作業フォルダ>` で束の一覧を出す。束は、**1つのエージェントの文脈に収まる大きさ**に切ってある（見込みトークンが予算 10 万以内。20 万の文脈の半分。字が小さく拡大して読むページは倍に数える。1束は 6〜7 ページになる）。カード済みのページは出ない。
2. 束ごとにサブエージェントを起こし、下の指示文を渡す。束どうしは独立なので、同時に 4〜6 束ずつ並べて進める。**親はページ画像もカードも読まない**（文脈があふれる）。サブエージェントの返事ではなく、報告のファイル（`reports/read_*.json`）と `python3 scripts/status.py -w <作業フォルダ>` で進み具合を見る。
3. 束が終わるたびに `python3 scripts/pages.py batches -w <作業フォルダ>` をもう一度。読み残したページ（報告の `pages_left`）は、半分の予算で束ね直されて出る。残りが無くなるまで繰り返す。
4. 全束が終わったら `python3 scripts/check_extract.py -w <作業フォルダ> --report <作業フォルダ>/out/チェック_読取.txt`。画面には同じ種類の行が 10 件までしか出ない（全件は `--report` のファイル）。FAIL は、そのページの担当に FAIL の行を添えて直させる（`--only M01 --pages 13-19` で束ごとに出せる）。WARN は1件ずつ見て、読み落としなら読み直させる。
5. 実際に使ったトークンが見込みと大きく違ったら、予算を変える（`--budget 80000`）。

サブエージェントを使えない環境では、親が1束ずつ同じ手順で読む。1ページ読むごとにカードを保存し、束が終わったら `status.py` で残りを確かめてから次に入る（前の束の画像の内容を持ち越さない。要るのはカードだけ）。

## 指示文の `{…}` に入れるもの

| 置き換える所 | 入れるもの | 例 |
| --- | --- | --- |
| `{WORK}` | 作業フォルダの絶対パス | `/Users/…/asis-flow-work` |
| `{SKILL}` | このスキルのフォルダの絶対パス（`scripts/` の1つ上） | `/Users/…/skills/asis-flow-skill` |
| `{DOC_ID}`・`{DOC_NAME}` | 束の一覧の資料 ID と、行の右のほうにあるファイルの相対パス | `M01`・`00_全体/経費精算業務マニュアル.pptx` |
| `{PAGES}` | 束の一覧の行末の `--pages` の値（ファイルの番号の範囲） | `13-18`（`3,5,8-10` の形も可） |

## サブエージェントへの指示文（ここからコピー。`{…}` を置き換える）

あなたは業務マニュアルのページを1枚ずつ読み、ページカード（JSON）に書き起こす担当です。書き起こしたカードだけが後の工程に渡り、業務フロー図になります。**ページに書いてあることだけを書いてください。書いていないことを補うと、誤ったフローがそのまま納品されます。**

### 読むページ
- 作業フォルダ: `{WORK}`
- 資料: `{DOC_ID}`（{DOC_NAME}）の、ファイルの番号 {PAGES}（`pNNNN` の番号。ページに刷られた番号とは違うことがある）
- 1ページごとに次の3つを読む:
  - 画像 `{WORK}/pages/{DOC_ID}/pNNNN.png` — **必ず Read で開いて見る**
  - 行の番号つきの文字 — `python3 {SKILL}/scripts/pages.py lines -w {WORK} --only {DOC_ID} --pages <ファイルの番号>`。機械抽出の文字を、文の単位に切って番号を振ったもの。**原文の場所は、この番号で指す**（原文を写さない）
  - 機械抽出 `{WORK}/pages/{DOC_ID}/pNNNN.json` — 図形・コネクタ（矢印がどの図形をつないでいるか）・表
- 画像の無いページ（マクロのソース・文字のファイル・非表示のスライドやシート）は、機械抽出の `text`・`shapes`・`tables` を読む。非表示のものも、ほかのページと同じに書く（非表示であることは、機械が資料の一覧から知り、確認事項「資料の版」に載せる）。

### 最初に読むもの
- `{SKILL}/references/flow-rules.md` の §0 と §1（読取の決まり。迷いやすい所の決め方は 1.14〜1.25）
- `{SKILL}/references/schemas.md` の「番号の2種類」と「ページカード」（書く形。**表に無い項目は足さない**）

### 読み方（1ページずつ、この順で）
1. 画像を開く。**まず、ページに刷られたページ番号を探して `printed_page` に書く**（上下の端。番号だけを書く。「- 13 -」は「13」。無ければ null）。`page` はファイル名の番号。
2. そのページが何のページかを、flow-rules.md 1.14 の表の上から順に当てはめて決める（`page_type`）。
3. 画像にあるものを上から順に読む。本文、図の中の文字、画面キャプチャの項目名とボタン、表、**注記・※・なお書き・ただし書き・囲み・表の欄外**、手書きの書き込み、ページの端の小さい字。
4. 機械抽出と突き合わせる。機械抽出にあって画像で見落とした文字がないか。画像で読んだ文字が機械抽出と違えば、画像を見直す。
5. フロー図は、箱を1つずつ、矢印を1本ずつたどって `diagram` に写す（箱の id は g1、g2…）。箱の中に作業の文が書かれているとき（見出しの下に「申請者は、申請書を作成して提出します。」）は、箱の見出しを `label` に、文を `steps` に書く（見出しだけの箱は `steps` に書かない）。機械抽出の `connectors` に from / to があれば、それが矢印の正解（図形の id は `shapes` の id）。本数を数えて合わせる。from / to が空の矢印や、機械抽出に無い矢印（画像として貼られた図）は、画像で向きを読む。向きが決まらなければ `uncertain` に書く。
6. 手順は、紙面に書かれた順に、**原文の1文（箇条書きなら1項目）を1つ**として `steps` に書く（順は、一般的な流れに合わせて入れ替えない）（id は s1、s2…。1文に動作がいくつあっても分けない。分けるのは、文の途中で担当が変わるときだけ）。**原文の場所は、行の番号で指す**: `lines` に `[開始, 終了]` を書く（1行だけなら `[7, 7]`。文が2行に分かれていれば `[7, 8]`）。**`quote` は書かない。** その行の文字を、あとで機械が入れる（写し間違い・言い換えが起きない）。分岐（`decisions`）・補足（`notes`）も同じ。行の番号つきの文字に無い文字（画像の中の文字・スキャンしたページ）から取ったときだけ、`from_image: true` にして `quote` に読んだ文字を写す（`lines` は書かない）。
   手順が使うシステム・ツール（システムの名前、マクロ・クエリを含むブックやファイルの名前、ツールの名前）は、その手順の `system` に、原典の呼び方のまま書く（帳票としてだけ書かない。箱の札と、プログラムとの紐付けに使う）。
7. **補足の中に「誰かが何かをする」が書かれていたら、それも `steps` に書き、`origin: note` にする。** 作業を含まない補足・例示（「例えば〜」）は `notes` に。「〜する」と書かれているが作業でないものは、`notes` に `why_not_action`（理由）つきで書く。ページの頭の「概要」の表（目的・内容・タイミング・担当者など）の「内容」欄の文は、手順にしない: `notes` に書き、`why_not_action` に「概要の表の文。手順は、業務の流れ以下に書かれている」と書く。**ただし、その文に書かれた作業・分かれ目が、業務の流れ以下（同じページの図の箱・手順、続くページの見出し）のどこにも出てこないときは、その文を手順（分岐）にする**（フローの作業のノードは、カードの手順・分岐を出典に引く。補足にすると、原典に書かれた作業なのに、フローでは推定の扱いになる）。そのときは `uncertain` に「概要の表にだけ書かれている。業務の流れのどこに入るか」を書く。表の「担当者」「タイミング」は、手順の担当・フローのきっかけの根拠に使う。
8. 機械抽出に `small_text: true` があるページ、または画像で字が読みにくいページは、拡大して読む:
   ```bash
   python3 {SKILL}/scripts/crop_page.py -w {WORK} {DOC_ID} <ファイルの番号>            # おすすめの分割で全体を拡大
   python3 {SKILL}/scripts/crop_page.py -w {WORK} {DOC_ID} <ファイルの番号> --region 0.5,0,1,0.5   # 一部だけ
   ```
   表示されたパスの画像を Read で開く。拡大しても読めないところは `unreadable` に書く。推測で埋めない。
9. 担当・順序・分岐の行き先が書かれていなければ、空にして `uncertain` に書く。前後のページから類推して入れない（前後のページは別のカードが受け持つ）。同じ番号つきの並びの中で、前の手順の主語が続いているだけなら、その主語を入れる。
10. **カードを保存してから、次のページの画像を開く。** 何ページ分もの画像を先に開いてから書くと、1つずれたページの内容を書いてしまう。途中で止まっても、保存したカードは残る。

### 書く場所
`{WORK}/cards/{DOC_ID}/pNNNN.json`（1ページ1ファイル。表紙・目次・白紙も書く）

### 終わったら（文脈の残りが少なくなって途中で止めるときも）
1. 引用を機械に入れさせてから、自分のページを確かめて、FAIL を直す:
   ```bash
   python3 {SKILL}/scripts/quotes.py fill -w {WORK} --only {DOC_ID} --pages {PAGES}     # lines の行の文字を quote に入れる
   python3 {SKILL}/scripts/validate.py -w {WORK} --kind card --only {DOC_ID} --pages {PAGES}
   python3 {SKILL}/scripts/check_extract.py -w {WORK} --only {DOC_ID} --pages {PAGES}
   ```
   「quote が無い」「行の番号が範囲の外」「引用が、指した行の文字と違う」は、`lines` を直して `quotes.py fill` をやり直す（`quote` を手で直さない）。「指した行が、書いた内容と合っていない疑い」は、別の行を指していないかを見る。「作業らしい文が、手順・分岐・補足のどれにも指されていない」は、その文を `steps` に書く（図の箱の中の文も）。作業でなければ `notes` に `why_not_action`（理由）つきで書く。
   「補足の中に作業らしい文がある」は、機械が拾った候補。作業なら `steps` に `origin: note` で足し、作業でなければ `notes` に `why_not_action` つきで書く。「引用がこのページに無く、… にある」「printed_page が…と違う」は、別のページを読んでいる印。画像を開き直す。
2. 報告を `{WORK}/reports/read_{DOC_ID}_<先頭のファイルの番号>.json` に書き、`python3 {SKILL}/scripts/validate.py --file report_read <そのファイル>` で形を確かめる（形は schemas.md の「報告と採否表」。崩れていると、親が次の束を作れない）。読めなかったページは `pages_left` に入れる。親が残りを別の担当に渡す。
3. 返事は1行だけ: 書いたカードの枚数と、残したページの数。カードの中身は貼らない。

## よくある失敗

| 失敗 | 何が起きるか | どうする |
| --- | --- | --- |
| 機械抽出の文字だけでカードを書く | 画像の中の文字・図の矢印が落ちる。機械抽出は読む順序も乱れる | 画像を必ず開く。`figures` に画像の中身を書く |
| `quote` を手で書く・要約を入れる | 指した行の文字と違うので FAIL になる | `lines` に行の番号を書き、`quotes.py fill` に入れさせる |
| 隣の行の番号を書く | 別の文が引用になり、フローの出典がずれる | `pages.py lines` の番号を、その文の行で確かめる。1文が2行なら範囲で書く |
| 「上長」を「課長」と書く | 別の担当が1人に化ける | 原文のまま。同じかどうかは確認事項 |
| 図の矢印を「左から右だろう」で決める | 逆向きの流れ・戻りの線が消える | コネクタを数える。決まらなければ `uncertain` |
| 画面キャプチャを「画面の図」で済ませる | 操作手順（どの項目に何を入れ、どのボタンを押すか）が落ちる | 項目名・ボタン名・入力例を `figures[].texts` に書く |
| 次のページの内容を先取りして書く・数ページまとめて書く | 出典のページがずれる | 1ページ読んだら保存してから次へ。`printed_page` を画像で確かめる |
| 注記（※・なお・ただし）を「補足だから」と読み飛ばす | 補足の中の作業がフローから落ちる | 作業なら `steps`（`origin: note`）、作業でなければ `notes` |
| 決まっていない項目（`header`・`memo` など）を足す | 形の点検が FAIL。担当ごとに形が変わる | 表にある項目だけを使う。当てはまらなければ報告の `hints` に書く |
| `page` に刷られたページ番号を書く | カードの置き場所と合わず、出典がずれる | `page` はファイル名の番号。刷られた番号は `printed_page` |
