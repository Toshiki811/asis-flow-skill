# テンプレートと、使い回している外部の道具

## 納品物の様式は、テンプレートで決める

納品物の欄と見た目は、`assets/` のテンプレートが決める。中身は、機械が同じデータから流し込む。**LLM は、テンプレートに書かない**（様式が、毎回同じになる）。お客様の様式に合わせるときは、テンプレートを差し替える。

| 納品物 | テンプレート | 読む道具 | 決まりを外れたとき |
| --- | --- | --- | --- |
| 業務フロー（draw.io） | `assets/業務フロー図_テンプレート.drawio` | `harvest_template.py` → `assets/template_styles.json` | `check_flow.py` が、テンプレートに無い色・形を FAIL にする |
| アクティビティ図（draw.io） | `assets/アクティビティ図_テンプレート.drawio` | `harvest_template.py` → `assets/activity_styles.json` | 同じ |
| 業務マトリクス一覧（xlsx。台帳の一覧・処理時間の基準を含む 11 シート） | `assets/業務マトリクス一覧_テンプレート.xlsx` | `table_template.py`（書き出すたびに読む） | `table_template.py check` が FAIL にする。書き出さない |
| 確認事項一覧（xlsx） | `assets/確認事項一覧_テンプレート.xlsx` | 同じ | 同じ |

テンプレートにしていないもの: 出典対応表・照合シート・チェック結果・採否表（点検用の紙）。図の 1 ページ目（全体構成／システムと起動点の一覧）の表の配置と、アクティビティ図の横並びの配置は、機械が決める。

## 所定テンプレート（業務フロー）

`assets/業務フロー図_テンプレート.drawio`（縦列レーン形式）。`scripts/harvest_template.py` がスタイルと寸法を `assets/template_styles.json` に抜き出し、`build_drawio.py` はそれだけを使って図を組む。`check_flow.py` は、図にテンプレートに無い色・形があれば FAIL にする。

テンプレートを差し替えるとき:

```bash
cp <新しいテンプレート.drawio> assets/業務フロー図_テンプレート.drawio
python3 scripts/harvest_template.py        # template_styles.json・activity_styles.json を作り直す
```

`harvest_template.py` は要素を id ではなく形で見分けるので、次の形を守ったテンプレートなら差し替えられる。

| 要素 | テンプレートでの形 | 図での使い方 |
| --- | --- | --- |
| レーン | 見出し（太字 14pt の四角）＋背景（`opacity` 付きの四角）。スイムレーン図形ではない。幅 300、左端 x=80、見出し y=80・高さ 40、中身は y=120 から | 担当ごとに1列。部門・役職はテンプレートの配色（青・紫）を交互に、システムは灰色 |
| 開始・終了 | 楕円（緑）120×60 | レーンの中央 |
| プロセス | 角丸の四角 150×70。レーンの色。「P-001: 名称」＋改行＋補足 | 高さは文字数に合わせて伸ばす。下段に出典 |
| システム処理 | 角丸の四角＋破線（灰色）。「S-001: 名称」 | 自動処理 |
| 判断 | ひし形（黄）150×80。「D-001」（小さい字）＋改行＋条件 | 条件の文は、機械が、ひし形の形に合わせて折る。高さは、文が収まるいちばん低い高さ（テンプレートの高さが下限） |
| ファイル | `shape=note`（黄）50×60。「F-001」＋改行＋名前 | プロセスの右（レーン左端から 240） |
| 通常の線 | 実線・#666666・太さ 2・直角 | 業務の流れ |
| システム連携の線 | 破線（8 8）・#0066CC・太さ 2 | 両端のどちらかがシステム処理 |
| 参照の線 | 点線（3 3）・#b85450・太さ 1.5・開いた矢じり | ファイルとプロセスの間 |
| 凡例 | id が `legend` で始まる部品 | 最後のレーンの右に置く |

全要素は `parent="1"` の絶対座標（レーンの子にしない）。行の間隔はテンプレートでは 110。

### テンプレートに無く、このスキルが足している表現

色はテンプレートにあるもの（参照線の赤 #b85450・ファイルの黄 #fff2cc・システム連携の線の青 #0066CC）だけを使う。`template_styles.json` の `extensions` にある。

| 表現 | 形 |
| --- | --- |
| 推定で置いたノード・線 | 赤い破線の枠・線 |
| 確認事項の番号 | 黄色い小さな楕円に赤字（Q-012）。ノードの右肩。線はラベルに〔Q-012〕 |
| 下位フロー | プロセスの形に左右の縦線（`shape=process`）。クリックで別ページへ |
| 札（使うシステム） | 箱の中の青い字「［会計システム］」。人がシステムを操作する作業に、機械が付ける（出典に引いた手順の `system` と、その文に出てくるシステム名）。補足の下 |
| 補足 | 箱の名前の下に、かっこ書き（機械が包む。動詞で終わる名前と、見分けられるように） |
| プログラムの起動点の箱 | システムのレーンのシステム処理の箱に、青い字「▶ A-02-1」（アクティビティ図の番号）。紐付けた手順を引く作業のすぐあとに、機械が置く。線は、システム連携の線 |
| 出典 | 枠の外の、小さい灰色の字「業務マニュアル p.3」（資料の題名とページ。資料ID は出さない）。箱・ひし形のすぐ下・真ん中の線の右に、機械が置く（置き場所は、テンプレートでは決まらない）。ページは資料に刷られた番号（PowerPoint はスライド番号、Excel は「請求管理「手順」シート C2」）。1か所1行で、切らない（幅を超える行は、折る）。出典の分だけ、行は高く、列は広くなる（レーンの幅は、テンプレートの幅が下限） |
| 図の題・全体構成へのリンク・フローの情報 | テンプレートの文字・注記のスタイル |

### 配置の決まり（`build_drawio.py`）

- 行: 線のつながりから決める（前のノードより下。戻りの線は数えない）。同じレーンの同じ行には1つだけ。
- 線: 横は行と行の間、縦はレーン左の空き（通り道）を通す。まっすぐ下に引けるものはそのまま。分岐の2本目以降はノードの横から出す。こうして線がノードを貫かないようにする（`check_layout.py` が確かめる）。
- ノードは `<object>` で包み、属性に `node_id`・`node_type`・`lane`・`src`（出典）・`quote`（引用）・`src_image`（出典ページの画像の場所）・`systems`（札）・`inferred`・`questions`・`tooltip` を持つ。draw.io でノードにマウスを乗せると出典と引用が出る。
- 四隅に見えない点を置き、PNG の範囲を配置と一致させる（照合シートの赤枠の位置合わせ）。

## アクティビティ図のテンプレート

`assets/アクティビティ図_テンプレート.drawio`。アクティビティ図で使う形を、1つずつ置いてある（見本の文字は、架空のもの）。`harvest_template.py` が `assets/activity_styles.json` に抜き出し、`build_activity.py` はそれだけを使う。配置・線・確認事項の番号・出典の出し方は、業務フローの図と同じ部品（`build_drawio.py` の `FlowDrawing`）。既定のテンプレートの色は、業務フローの所定テンプレートにあるものだけ（開始・終了の黒を除く）。

差し替えるとき:

```bash
cp <新しいテンプレート.drawio> assets/アクティビティ図_テンプレート.drawio
python3 scripts/harvest_template.py        # template_styles.json・activity_styles.json を作り直す
python3 scripts/build_activity.py -w <WORK> && python3 scripts/check_flow.py -w <WORK> --stage drawio
```

試しに1回だけ別のテンプレートで描くなら、`harvest_template.py <テンプレート> -o <出力.json> --activity` → `build_activity.py --styles <出力.json>`。点検は `assets/` のテンプレートで確かめるので、納品するときは `assets/` を差し替える。

要素は、業務フローと同じく、形で見分ける。次の形を守る。

| 要素 | テンプレートでの形 | 図での使い方 |
| --- | --- | --- |
| レーン | 業務フローと同じ（見出し＋背景）。左から、操作者／プログラム／外部。外部は、破線の箱（下の「外部」）を置いたレーン | 操作者（人が見る・答える所）／プログラム（システム名）／外部（メール・ほかのプログラム）。使わないレーンは出ない |
| 開始・終了 | 黒丸（`shape=startState`）・二重丸（`shape=endState`） | 途中で終わる終了には、丸の横に小さく「終了（途中で終わる）」「プログラムを止める」 |
| 処理 | 角丸の四角。角の丸み（`absoluteArcSize`・`arcSize`）は、処理の箱だけに掛かる | 「P-001: 名前」＋補足＋もとのソースの場所（資料・モジュール・行） |
| 判断 | ひし形 | 業務フローと同じ |
| 別ページの処理の呼び出し | 角丸の四角＋`shape=process`（左右に縦線） | クリックで、その図のページへ |
| シート・ファイル・テーブル | `shape=note` | 読む・書くを、点線の矢印の向きで |
| 外部 | 角丸の四角＋破線 | メールを送る・ほかのプログラムを動かす |
| 線 | 通常（実線）／外部との連携（破線）／読む・書く（点線） | 業務フローと同じ |
| 凡例 | id が `legend` で始まる文字の箱 | **文は、書いたものがそのまま出る**（1行を `<br>` で区切る）。箱の幅も、テンプレートのもの |
| 図のメモ・小さい字 | 塗りのある文字の箱（図のメモ）・塗りの無い文字の箱（図の題・リンク・終了の種類） | 中身は、機械が書く |

テンプレートで決まるのは、形・色・字・寸法・凡例の文。分かれた道を横に並べる配置（`flow-rules.md` 4.11）と、1ページ目（システムと起動点の一覧。業務マトリクス一覧の「システム一覧」と同じ中身の表と、起動点の一覧。番号から各ページへ飛べる）の組み方は、機械が決める。

業務フローの図とアクティビティ図は、別のファイル。行き来は、番号の文字で引く（業務フローの箱の「▶ A-02-1」⇔ アクティビティ図の情報欄の「使われる業務: 業務フロー F01 S-001」）。

## 表のテンプレート（xlsx）

`assets/業務マトリクス一覧_テンプレート.xlsx`・`assets/確認事項一覧_テンプレート.xlsx`。`build_matrix.py`・`build_reports.py` が、書き出すたびにテンプレートを開き、行を流し込んで保存する（`scripts/table_template.py`）。

| テンプレートの部分 | 決まり |
| --- | --- |
| 表のシート | `{…}` の印がある行が「見本の行」。印（`{質問}`・`{大分類}` …）が、機械が埋める欄。見本の行の書式（字・塗り・罫線・折り返し）を、データの行すべてに写す。その上の行は、見出し・表題として、そのまま出る。印の名前と、既定の見出しが違う欄がある: `{きっかけ}`＝開始条件／`{成果}`＝終了条件／`{処理時間の合計}`＝処理時間の合計（分・全作業）／`{件数}`＝件数（人が入れる）／`{略称}`＝資料の題名（資料一覧の 1 列目。資料ID ではなく、題名が入る） |
| シートの名前 | 自由（どの一覧かは、印で決まる）。既定は、業務マトリクス・業務フローのノード一覧・システム一覧・プログラムのノード一覧・プログラムの図にしない手続き・プログラムの用語対応・縦軸の根拠・資料一覧。前の名前（ノード一覧・処理ノード一覧・図にしない手続き・用語の対応）のシートも、その一覧として受ける。起動点一覧は、既定の様式には無い（アクティビティ図の1ページ目にある）。シートを置けば出る（印は `{起動点}` `{システム}` `{きっかけ}` …）。システム一覧の `{起動点}`（数）の欄も、既定の様式には無い |
| 空の一覧 | プログラム用の一覧（起動点一覧・プログラムのノード一覧・プログラムの図にしない手続き・プログラムの用語対応）は、中身が1行も無ければ（プログラムを読んでいない）、ブックに入れない。あとからプログラムを足して、書き出し直していないブックは、点検が FAIL にする |
| 人が埋める列 | 印の無い列（確認事項一覧の 回答・回答者・回答日 など）。見本の行に書いた文字・書式・入力規則（選択式）を、すべての行に写す。書き出し直しても、人が書いた値は同じ行に戻る（下の「引き継ぐもの」） |
| 繰り返す列 | 業務マトリクスの作業の列（印は `{作業}`、見出しは `①`）。1つだけ置く。機械が、要る数だけ ②③… と繰り返す。その右に置いた欄（人が埋める列など）は、増えた列のぶん、右へ送る（既定の様式では、`{件数}`・`{処理時間の合計}` は、作業の列の左） |
| 基準の表 | 名前（定義された名前）`処理時間の表` の付いた範囲（既定は、シート「処理時間の基準」）。1 行目が見出し（`小`・`中`・`大`・`特大`。`特大` の列は、無くてもよい — 無ければ、量が特大の作業は `大` の列を引き、そう知らせる）、1 列目が動作の種類（15 語）、中は分（0 以上の数）。機械は、この名前で表の場所を知り、仮の処理時間のセルに、表を引く式（`VLOOKUP`）を書く。**この名前が無いテンプレート（前の形）には、既定のテンプレートから補って、書き出す**（基準の表のシートと名前・「書式の見本」の処理時間の行・処理時間の欄 `{処理時間の合計}` `{件数}` と、ノード一覧の `{動作の種類}` `{量}` `{処理時間（分）}` `{時間の根拠}`。欄は、右端に足す。テンプレートのファイルは変えず、補ったことを知らせる）。どのテンプレートでも、最初の出力から、処理時間が出る。補うのは、基準の表が無いときだけ（基準の表があって、欄を消してあるテンプレートは、消したまま出す） |
| 処理時間の行 | 基準の表があるとき、業務マトリクスは 1 フロー＝2 行（作業の行・そのすぐ下の、処理時間（分）の行）。時間の行の書式は、「書式の見本」の「処理時間の行」（塗りと、字の位置）・「処理時間」（人が入れた値の字）・「処理時間（仮）」（式のセルの字。条件付き書式 `ISFORMULA` で掛かる）・「処理時間（長い作業）」と「処理時間（仮・長い作業）」（量が特大で、まだ仮の値のセルの塗りと字。そのセルだけの条件付き書式で掛かり、数を打つと消える。この 2 行は、無くてもよい — 無ければ、ふつうの仮の値と同じ見た目）。`{処理時間の合計}` は、時間の行に、その行の足し算の式が入る欄。`{件数}` は、時間の行に置く、人が埋める欄（仮の値は入れない）。どちらも、消せば出ない。式のセル（仮の値・合計・ノード一覧の時間と根拠）には、計算の結果も保存する（計算をしない表示 — Finder・メールのプレビュー、Excel の保護ビュー — でも、最初から値が出る。Excel・LibreOffice は、開くときに計算し直す） |
| 文のシート | 見本の行が無いシート（読み方・表紙など）。そのまま出る。文の中の `{フローの数}` のような印にだけ、機械が数を入れる |
| シート「書式の見本」 | A 列＝名前、B 列＝見本のセル。判断・別フロー・システム・推定・帳票の塗りと、セルの中の字の種類（担当・出典・確認事項の番号 ほか）を、ここから読む。出力には入れない |

**変えてよいもの**: シートの名前と並び／見出しの文字／列の順／列の幅・字・塗り・罫線・折り返し・固定する枠・フィルター・印刷の設定（用紙・向き・ヘッダーとフッター）／見出しの上の表題の行（結合したセル・ロゴの画像）／人が埋める列を足す／任意の欄・任意のシートを消す／「読み方」の文／「書式の見本」の塗りと字／基準の表の数・行の順・説明・置き場所（シートの名前も）。

**守るもの**:

- `.xlsx` だけ（マクロ付きの `.xlsm`・古い `.xls` は、受け取らない）。
- 印は、1つのセルに1つだけ。見本の行は、シートに1行だけ。見本の行より下は、空にする。
- 点検が使う欄は、消さない: 業務マトリクス（大分類・中分類・`{きっかけ}`＝開始条件・フロー全体の確認事項・作業）／業務フローのノード一覧（大分類・中分類・フローID・ノード番号・行き先）／確認事項（番号・質問）。
- 「書式の見本」の A 列の名前の行を、消さない（「処理時間の行」「処理時間」「処理時間（仮）」の 3 行は、基準の表を置くときだけ要る。「処理時間（長い作業）」「処理時間（仮・長い作業）」は、無くてもよい）。
- 基準の表は、1 列目の語（動作の種類 15 語）と、見出しの `小`・`中`・`大`・`特大` を変えない（式が、この語で引く）。数は、0 以上の数で書く（既定は、人の作業と判断が 1 以上、システムの自動処理・別のフローへ続く箱が 0）。
- 使える印は、既定のテンプレートの見本の行に、全部書いてある（知らない印は FAIL）。

差し替えるとき（既定のテンプレートを写して、Excel で直すのが早い）:

```bash
cp assets/業務マトリクス一覧_テンプレート.xlsx <様式.xlsx>                       # 写して、Excel で直す
python3 scripts/table_template.py check <様式.xlsx> --book matrix                # 確認事項一覧は --book questions。FAIL 0 に
python3 scripts/build_matrix.py -w <WORK> --template <様式.xlsx>                 # 確認事項一覧は build_reports.py --template
python3 scripts/check_flow.py -w <WORK> --stage matrix                           # 書き出した本が、データのとおりか
python3 scripts/table_template.py supply <様式.xlsx> -o <様式_処理時間つき.xlsx>    # 基準の表の無い様式（前の形）に、処理時間に要るものを補って、別の名前で保存する
```

基準の表の無い様式は、そのままでも書き出せる（書き出すたびに、既定のテンプレートから補う）。補った欄の場所・基準の表の数を、様式の側で決めておきたいときは、`supply` で保存した様式を直して使う。

いつもその様式で出すなら、`assets/` のファイルを置き換える（`--template` が要らなくなる）。`check` は、機械が埋めない列（人が埋める欄）と、テンプレートに無い欄（出さない欄）も一覧に出す。

- 書き出すと、列の対応を、本のとなりに残す（`out/<本の名前>.columns.json`）。点検が、それを通して本を読み戻す。本だけを別の所に移して点検するときは、一緒に移す。前の版のスキルで書き出した本（列の対応が無い）は、`build_matrix.py` を実行し直せば、点検できる。
- **人が埋める列（回答・回答者・回答日・様式で足した列）は、引き継ぐ。** `build_reports.py`・`build_matrix.py` は、書き出す前に、いまある本から、行の鍵で作業フォルダの `answers.json` に取り込み、書き出しで同じ行に戻す。鍵は、確認事項一覧は番号、業務マトリクスはフロー（処理時間の行も）、業務フローのノード一覧はフロー ID とノード番号（並べ替えた本からも取り込める）。日付は、日付と表示の形のまま戻る。ほかの一覧に足した人が埋める列は、引き継がない（値があれば、書き出しが知らせる）。戻ってきた別の名前の本は `--keep <本.xlsx>`。列を足した・動かした本（見出しが書き出したときと違う）・業務マトリクスの行を動かした本・開いたままの本・読めない本は、取り込まずに止まり、上書きしない（`--fresh` で、いまの本から取り込まずに作り直す。`answers.json` にある値は戻す）。本で値を消すと、`answers.json` からも消える。確認事項が無くなった回答・取り込んだあとで質問の文が変わった回答・回答済みなのに残っている確認事項は、点検（`check_flow.py --stage reports`）が WARN で知らせる。
- **業務マトリクス一覧の、処理時間・件数・基準の表の数は、引き継ぐ。** `build_matrix.py` は、書き出す前に、いまある `out/業務マトリクス一覧.xlsx` から、数が直に入っている時間のセル（式でないもの。「8分」のような字も、数として読む）・件数・基準の表の、人が直した数を、作業フォルダの `times.json` に取り込み、書き出しで戻す（基準の表は、書き出したときの値と違う数が、人が直した数。書き出したときの値は、列の対応 `columns.json` の `table` に控えてある — テンプレートの表を変えたあとで書き出し直しても、ブックに残る前の値を、人の直しと見ない）。戻ってきた別の名前のブックは `--keep <ブック.xlsx>`。だれのセルかは、セルのコメントの 1 行目（「処理時間 F03 P-003｜…」「件数 F03｜…」）で突き合わせるので、行・列を入れ替えても合う（コメントを消したセルは、書き出したときの番地で突き合わせる）。同じ作業名の箱が 2 つ以上あるフローでは、コメントの「担当: …｜前: …」の行と、`times.json` の `lane`・`after` で、番号がずれても、もとの作業に付け替える。Excel で保存したブックも、そのまま取り込める（`evals/excel_check.py` で確かめた。Excel は、式のシート名の引用符を外して保存するが、点検・取り込みは、同じ式と見る）。数を消すと、仮の値（式）に戻る。いまあるブックを読めないとき・時間や件数のセルに数として読めない値（「1時間」「10〜15」）があるときは、上書きせずに止まる（`--fresh` で、取り込まずに作り直す）。ほかのオプション: `--calibrate`（人の値が 3 つ以上ある「動作の種類 × 量」を、その中央値に引き直す）／`--accept`（作業名が変わった箱の値を、そのまま認める）／`--forget`（無くなった箱の値を消す）。
- 実物で確かめたこと: 列の入れ替え・見出しの変更・シートの名前の変更・任意の欄を消す・表題の行（結合したセル）・選択式の列・塗りの変更・ロゴの画像・ヘッダーとフッターが、書き出した本に残り、LibreOffice で開ける。図形（オートシェイプ）・グラフ・テンプレートに自分で足した条件付き書式は、確かめていない（写らないことがある）。処理時間の行（式・条件付き書式・名前の付いた範囲・人の値の引き継ぎ）は、LibreOffice で計算し直して確かめた。Excel で保存した本の取り込みは、`evals/excel_check.py` で確かめた。
- 欄を足す・減らすとき（スキルを直す人）: `build_matrix.py` の `HEADS`・`build_reports.py` の `Q_HEAD` を直し、`python3 scripts/table_template.py default` で既定のテンプレートを作り直す（`evals/selftest.py` が、既定のテンプレートと作り方のずれを見つける）。

## 使い回している外部の道具・スキル

| 工程 | 使っているもの | 用途 |
| --- | --- | --- |
| ページ化 | PyMuPDF（`fitz`） | PDF のページ画像・文字層・しおり |
| ページ化 | Microsoft PowerPoint / Excel / Word（macOS・AppleScript）または LibreOffice | Office 文書を見た目どおりの PDF に。PowerPoint の手順は consulting-pptx-skill の `export_deck.py` と同じ |
| 機械抽出 | python-pptx・openpyxl | スライドの図形とコネクタ・表・ノート、セルの値 |
| 機械抽出 | oletools（`olevba`） | マクロ（VBA）のソースを、実行せずに取り出す |
| 機械抽出 | 自作（`render_pages.py`） | Excel のシートに描かれた図形とコネクタ（`xl/drawings/*.xml`）。既製のものが見当たらなかった |
| 読取 | Claude の画像読取（Read） | ページ画像を見て読む。OCR は使わない |
| 作図 | draw.io デスクトップのコマンド（`drawio -x -f png -p N`） | PNG への書き出し |
| 表の書き出し | openpyxl（`table_template.py`） | xlsx のテンプレートを開いて、行を流し込む。ロゴの画像を残すのに Pillow |
| チェック | consulting-pptx-skill の方式 | 正典 → 機械チェック FAIL 0 → 画像で目視 → 作り方を知らない別エージェントのレビュー → 採否表 |
| スキルの作り | Anthropic の skill-creator | 構成・説明文・評価 |

draw.io の XML の決まりは、jgraph/drawio-mcp の `shared/xml-reference.md`（<https://github.com/jgraph/drawio-mcp>。Apache-2.0）が詳しい。このスキルが守っているのは、根のセル（id 0 と 1）、セルごとに重ならない id、線には必ず `mxGeometry`、ラベルの `<` `>` `&` の退避、XML コメントを書かない、の5点（`build_drawio.py` が XML を組むので、手で気にすることはない）。図を手で編集したい・ほかの種類の図も作りたいときは、同リポジトリの drawio スキル（`/plugin marketplace add jgraph/drawio-mcp`）が使える。

Anthropic の `pdf`・`pptx`・`xlsx`・`docx` スキルは、個別の資料を詳しく調べたいとき（PDF のフォーム、Excel の数式、Word の変更履歴）に使う。このスキルのページ化は、それらと同じライブラリを直接使っている。
