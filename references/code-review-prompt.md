# アクティビティ図の原典照合（レビュー担当への指示文）

アクティビティ図を、作り方を知らない別のエージェントが、もとのソースと突き合わせる。業務フローの原典照合（`source-review-prompt.md`）と同じ考えで、**作った側の説明を渡さない**（直しの一覧・構造のファイルは見せない）。見せるのは、図（PNG）と、行の番号つきのソースと、業務マトリクス一覧（「プログラムのノード一覧」「プログラムの用語対応」）。

図の箱は、業務の言葉で書いてある（読むのは、業務部門の担当。変数・項目・手続きの名前は、箱に出ない）。だから、照合は「同じ文字があるか」でなく、「**その行のしていることを、正しく言い表しているか**」で見る。

親がやること:

1. `python3 scripts/check_flow.py -w <WORK> --stage activity` と `python3 scripts/check_layout.py -w <WORK>` を FAIL 0 にしてから始める（照合に出す図に、【下書き】が無いこと）。
2. 図を 3〜5 枚ずつに分け、1組を1つのサブエージェントに渡す（同時に 4 体まで）。呼び出しの箱がある図は、呼ばれる側の図と同じ組にする。渡す前に、組ごとに `python3 scripts/review.py record -w <WORK> --only <図の番号,…>` で、照合に出す版を控え、出たシートの番号（S-<n>）を指示文の `{シートの番号}` に入れる（どの版の図を照合したかは、この番号で決まる。照合のあとに図を直したかを、点検がこの控えと比べる）。
3. 返ってきた報告（`reports/code_review_<先頭の番号>.json`）から、`python3 scripts/review.py draft -w <WORK>` で、図ごとの採否表 `review/<図の番号>.review.json` の下書きを作る（見た箱 `checked` のうち、指摘の無い箱は「支持」、指摘のある箱は「不支持」。`checked` に無い箱は判定なし。報告の形が崩れている・図に無い箱を指す指摘があれば止まる）。指摘ごとに `decision`（採用／不採用／保留）と `action` を書く。採用した指摘は、直しの一覧（`activities/<番号>.edits.json`）を直して `activity.py apply` からやり直す。図のデータ・XML は手で直さない。機械の取り出しの誤り（分岐・入出力・起動点の拾い違い）と分かった指摘は、スクリプトの不具合として記録し、利用者に知らせる。

指示文（`{…}` を埋めて渡す）:

```
あなたは、プログラムのアクティビティ図を、もとのソースと突き合わせるレビュー担当です。図の作り方は知らされていません。
プログラムは実行しません。読むだけです。

対象の図: {番号の並び}
図の画像: {WORK}/out/png/アクティビティ図_pNN_act-<番号>.png
箱の一覧: python3 {SKILL}/scripts/pages.py lines -w {WORK} --only <資料ID> --pages <ページ> で、ソースを行の番号つきで見られる。
          箱の下の「出典: 「月次集計」31〜37 行」（資料の題名とモジュール。同じ名前なら 1 回）の行は、モジュールの行の番号。ページの先頭に「このページの 1 行目は、モジュールの N 行目」と出るので、読み替える。
          業務マトリクス一覧（{WORK}/out/業務マトリクス一覧.xlsx）の「プログラムのノード一覧」に、箱ごとのソースの場所と、対象外にした文がある。
          「プログラムの用語対応」に、プログラムの中の名前（変数・項目・手続き）を、図でどの言葉で書いたかと、その根拠（コメント・定義・つづりからの推定・不明）がある。

図を読むのは、業務部門の担当です。箱は、業務の言葉で書いてあります（変数・項目・手続きの名前は、箱に出ません）。

図ごとに、次を確かめる。

1. 箱1つずつ: 出典の行を読み、箱の名前が、その行のしていることを言い表しているか。
   ・していないことを書いていないか（ソースに無い処理・名前・数字）
   ・かぎかっこの中の名前（シート・ファイル・テーブル・画面・ボタンの文字・メッセージ）が、ソースの文字のままか
   ・業務の言葉に直した名前が、その行の変数・項目の意味と合っているか（「プログラムの用語対応」の言葉が、定義・コメントと食い違っていないか。
     根拠が「つづり（推定）」の言葉は、読み方が無理でないか）
2. 判断1つずつ: 条件と、出口のラベルの向きが、ソースと合っているか（「はい」と「いいえ」が逆になっていないか。Else の側の行き先）。
3. 流れ: 箱の順・分岐の合流・繰り返しの戻り先・途中で終わる所が、ソースの順と合っているか。
4. 読む・書く: 箱に付いたシート・ファイル・テーブルと、その向き（読む／書く）が、ソースと合っているか。抜けていないか。
5. 落ちているもの: 「プログラムのノード一覧」で対象外・畳んだとされた文を読み、業務の上で意味のある処理（シートやファイルへの書き込み・金額や日付の条件・利用者への問い）が、
   対象外や畳みに入っていないか。
6. as-is: 改善案・不具合の指摘が、箱や補足に書かれていないか。
   ・箱の名前が、動詞で終わっているか（体言止めでないか）。出典（箱・ひし形の右下の灰色の字）が、切れずに読めるか。
   ・「確認事項一覧」の、その図の問いが、答えで図が変わる問いか（値だけ・いまも同じかの確かめ・名前だけの問いが、混ざっていないか）。
7. 図にしない手続き（「業務マトリクス一覧」の「プログラムの図にしない手続き」のうち、対象の図が呼ぶもの）: その手続きのソースを読み、
   ・理由（探す・取り出す／寸法・位置・単位の計算／文字・日付の整形／保存先・名前の組み立て／ログの表示／型・空・エラーの種類の確かめ）が、中身と合っているか
   ・業務の計算・判定（金額・税・件数・期限・区分）や、シート・ファイル・テーブル・画面への書き込み・メッセージが、中に入っていないか
   ・呼ぶ側の箱の名前が、その手続きのしていることを言い表しているか（呼ぶ側の箱として、1 に数える）
   合わないものは、findings に kind「図にしない理由が違う」で書く（node は空。what に、手続きの名前と行）。
8. 読む人に通じるか（別枠。支持率には数えない）: 業務部門の担当が読んで分からない言葉（プログラムの中の名前がそのまま・技術の用語・
   意味の取れない略語）が、箱・判断・出口・図の名前に残っていないか。見つけたら readability に書く。

報告を {WORK}/reports/code_review_{先頭の番号}.json に書く:
{"sheet": "{シートの番号}",
 "activities": [番号…],
 "checked": {"A-02-1": ["P-001", "P-002", "D-001", …]},     ← 図ごとに、ソースと突き合わせた箱の番号（開始・終了を除く）。見ていない箱は書かない
 "findings": [{"activity": "A-02-1", "node": "P-004", "kind": "名前が違う|していないことを書いている|条件・出口が逆|流れが違う|読む・書くが違う|落ちている処理|図にしない理由が違う|as-is でない",
               "source": {"doc_id": "M02", "page": 1, "lines": [23, 27]}, "what": "何が違うか（ソースの文字を引く）"}],
 "readability": [{"activity": "A-02-1", "node": "P-004", "word": "通じない言葉", "why": "なぜ通じないか"}]}

指摘（findings）は、ソースの行を示せるものだけを書く。好み・書き方の提案・改善案は書かない。業務の言葉への言い換えそのもの（変数の名前が箱に無いこと）は、指摘にしない。
見つけたことは、図を1枚見終わるごとに、報告のファイルに書き足す（途中で止まっても、そこまでが残るように）。
```

照合のあとに図を直したとき（採用した指摘の反映も含む）は、点検（`--stage review`）が挙げる「照合したあとに変わった・足した箱」だけを照合し直す（差分照合。考え方と手順は `source-review-prompt.md` の「差分照合」と同じ）。`python3 scripts/review.py record -w <WORK> --only <図の番号> --nodes <箱の番号>`（点検が「図の項目」を挙げたら、`図の項目` も）で、差分照合に出す版を控え（出たシートの番号を `{シートの番号}` に）、上の指示文の「対象の図」を、その図 1 枚にし、最後に「この照合は、差分照合です。{箱の番号} の箱だけを、1 つも抜かさずに確かめてください（`checked` には、その箱だけ）。「図の項目」が挙がっていれば、図にしない文・分岐の理由をソースと比べ、違えば指摘に書いてください（`checked` には書きません）。ほかの箱は、前の照合で済んでいます」と足す。報告は `reports/code_review_<図の番号>_差分<N>.json`（`review.py record` が、まだ使っていない番号で出す置き場。前の報告を上書きしない）に書かせ、`python3 scripts/review.py draft -w <WORK> --only <図の番号>` で写す（判定は照合に出した順に重ね、差分照合が判定した箱は、前の判定を置き換える）。

支持率は、機械が数える（`checked` に書いた箱のうち指摘の無かった箱 ÷ 開始・終了を除く全部の箱。`checked` に無い箱は、照合していない箱として分母にだけ入る）。報告に無い図を指す指摘・照合に出していない箱の判定・記録に無いシートの番号があると、`review.py draft` が止まる（報告を直す）。`python3 scripts/check_flow.py -w <WORK> --stage review` が、95% 未満を FAIL にする。親は、支持率と、指摘の件数（種類別）と、通じない言葉の件数（`readability`。支持率とは別）を、利用者への報告に入れる。
